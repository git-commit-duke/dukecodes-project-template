## Themes

- **One writer, fresh-context read-only reviewers** (6 sources): Reviewers are repo-defined subagents with a Read/Grep/Glob allowlist, so read-only is enforced by the tool list, not the prompt. Every other writer path is closed off: forks, general-purpose, the claude catch-all, teams, /batch, EnterWorktree, isolation: worktree, pr-review-toolkit agents, and workflow change stages.
- **Only committed config reaches cloud build sessions** (6 sources): The maintainer agent and the checkpoint and session-close skills now live only in ~/.claude. Cloud sessions load neither user agents nor user settings, so these must move into the template. Effort, env pins, denies, messaging posture and hooks go in the single root .claude/settings.json. Plugins go through the claude.ai account.
- **GitHub Issues are the only ledger; side channels are refused** (7 sources): Findings, plan summaries, fallback notices and handoffs go to Issue or PR comments. No team task lists, peer messages, in-repo sprint files or local session logs serve as state.
- **Gates must be deterministic and fail closed** (6 sources): Hook scripts must exit 2 on any internal error. Hooks.md:864 (read raw): exit 1 does not block, so a crashing guard fails open. CI repeats every hook check and lints the settings posture, since agent-writable config is untrusted. A push to main is denied, not just warned about.
- **Right specialist means a model and effort pair chosen by risk and backstops, not by rank** (4 sources): Opus goes where a miss would escape CI and the maintainer and cause damage outside the repo. Sonnet goes where two backstops cover a narrow lens. Haiku goes to reversible mechanical work. xhigh is the ceiling for standing configuration. Effort is always declared together with the model.
- **Keep always-loaded context lean and load the rest on demand** (5 sources): The root CLAUDE.md stays a short spine. Area rules go in path-scoped .claude/rules/ (add .github/workflows/** and infra globs), and procedures go in a few skills. Security detail stays in path-scoped rules, which also avoids first-request classifier fallback. Keep the roster small, unlike CCGS's 49 agents.
- **Silent model and effort drift must be surfaced** (3 sources): A cyber-flag fallback keeps the session on Opus 4.8. Because the opus alias follows the main session's Opus-family model (sub-agents.md:361-362, read raw), every Opus reviewer drops too. Verdicts must name their model, and a PostModelSwitch hook (it fires on automatic fallback) should put a notice in context for checkpoint to record.
- **Parallelism is bounded by issues, not by agent count** (5 sources): 2-3 owner-started sessions on separate issues, with declared areas and cuts along coupling boundaries. Reviewer fan-out stays at about three lenses. Workflow size stays at medium, piloted small first.
- **Agent view, Projects and worktrees solve problems Kernel avoids** (4 sources): The owner tracks sessions in the claude.ai/code list and in Issues, not in a local dispatcher. Worktrees stay a local convenience only: ignore .claude/worktrees/, deny EnterWorktree, never give reviewers isolation: worktree (they would review main instead of the change), and have gate hooks read cwd from the input JSON.
- **Cross-session messaging gets a closed, checked-in posture** (2 sources): Messaging is on by default and a refusing session looks no different at runtime. So the template commits refuse inbound and approval for outbound, CI asserts both, reviewer allowlists exclude SendMessage and ListAgents, and CLAUDE.md states that agent and peer text is never owner consent.
- **From CCGS, borrow the gates, not the org chart** (2 sources): Adopt: SessionStart orientation, an audit trail of subagent runs, POSIX-portable hooks, UPGRADING.md with a split between template-owned and repo-owned files, and review depth scaled by a risk label. Reject: tiered hierarchies, delegation to agents, fail-open hooks, push warnings instead of denies, and a no-gates review mode.
